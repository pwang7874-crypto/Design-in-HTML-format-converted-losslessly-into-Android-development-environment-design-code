# Kotlin/Jetpack Compose 转换

最后一步使用现有网页源码、原始 HTML 与 restore-pack 完成原生工程。已有网页源码时直接分析和复用其数据与行为，不要求再次提取或重写已验证的网页。

## 保留什么

- 逐项映射页面、子状态、输入/搜索、展开/收起、分类/订阅、错误/空/加载/重试、返回路径、时间延迟与反馈。按原型实际存在的行为实现，不把某一示例应用的功能清单套到其他原型。
- 示例数据和原文独立放在 JSON、Kotlin 数据模型或 Android resources；重复条目用 Compose 组件和列表渲染，图片与图标转换为本地 Android 资源。
- 视觉 token 转为 Compose 的颜色、排版、圆角、阴影与间距。用 Column、Row、LazyColumn/LazyRow、FlowRow、Box 等构建适应屏幕的布局；Canvas/SVG 内部坐标只用于图表或图形，不能用截图 box 坐标排列整个界面。
- 页面使用原生 Compose 与状态导航。完整交付不能仅以 WebView 加载 HTML 或保留一组未接入入口的 Composable 作为完成。
- 处理系统返回键、键盘、滚动、窗口 Insets 和状态保存；保留原型明确要求的返回/滚动关系。悬停等网页交互按触控或焦点方式适配，并记录实际差异。
- 按钮在原型中只显示演示反馈时，保留该反馈并注明边界；原型没定义的定位、地图拖动、语音、分享、登录或服务端接口不得被声称已实现。

Android 自己绘制状态栏、时间、电池和手势条。网页中的假手机外框和浏览器/扩展元素不进入原生页面。字体、输入控件和系统行为的必要适配在工程 README 说明。

## 工程与验证

1. 检查可用 JDK、Android Studio、SDK、Gradle 和依赖缓存，选择兼容的工具版本。使用可用工具生成完整 Gradle Wrapper（含 jar 与脚本），不要固定为某台电脑或本次示例的版本与 SDK 路径。
2. 接好 Activity/入口、Manifest、Compose 主题、页面状态、资源与模块配置；项目根目录须有 `settings.gradle.kts`、构建配置、Wrapper、`app/` 和 README。
   工程保存在用户项目或当前工作区的交付目录。`tools/restore-pack` 会被下一次测量替换，不能用于保存最终工程。
3. 执行与变更相称的构建和检查，通常包括 `assembleDebug`。数值转换或状态转换确有需求时使用有意义的测试；不为说明文案或简单可逆编辑增加镜像测试。
4. 有合适模拟器时验证启动和核心点击路径，检查运行时错误。测试结果必须区分实际运行、静态审查和未执行项；没有环境时完成工程并准确说明限制。
5. 交付实际构建出的调试 APK及完整源码工程。源码压缩包排除构建缓存、生成目录和机器专用 SDK 配置；在本机使用的工程中可保留正确的 `local.properties`。

## README 必须让开发能接手

- 给出可复制的工程根目录绝对路径；Android Studio 通过 **File → Open** 打开根目录，而非仅打开 `app/` 或某个 Kotlin 文件。说明 Gradle Sync、JDK/SDK 选择、Run 的入口。
- 写明采用的工具版本、构建命令（Windows `gradlew.bat assembleDebug`，其他平台 `./gradlew assembleDebug`）、测试命令与 APK 的实际位置。
- 列出界面、每条交互从哪里到哪里、数据/文案/资源/状态/组件的维护入口。
- 标注示例数据、演示反馈、待真实接口及原型未定义的入口，记录安卓适配与尚未消除的差异。
- 写明实际完成的构建、测试、模拟器检查和未执行项；调试 APK 与正式发布签名/上线区别清楚，不扩展为发布任务。
